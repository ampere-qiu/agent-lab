## アルフレッドとパーティーの準備 { #introduction }

アルフレッドは、ウェイン邸でスーパーヒーローをテーマにしたパーティーを準備する架空のアシスタントです。音楽、メニュー、ケータリング、パーティーのテーマを選ぶ仕事を通して、エージェントを学びます。

## フレームワークの役割 { #what-the-framework-does }

**smolagentsは、エージェントを作るためのPythonライブラリです。** CodeAgentと、モデルとツールをつなぐループの仕組みを提供します。

- **Groq上のモデル**が、依頼を読んでアクションを提案します。
- **自分のPC上のPython**が、そのアクションを実行し、結果またはエラーを返します。
- **自分のPC上のCodeAgent**が、問い合わせ、実行、観測結果、最終回答の流れを管理します。

フレームワークはタスクと実行履歴を保持し、使えるツールをモデルに伝え、提案されたアクションを実行して観測結果を返します。どのツールを用意するか、入力をどう説明するか、何を登録するか、結果が正しいかを確認するのは自分の役割です。

## どんなときに役立つ？ { #when-useful }

フレームワークがあると、少ないコードで始めて試せます。モデルにツールを選ばせたいときや、何段階かに分けて仕事を進めたいときに役立ちます。

たとえば、プログラムがすでに`15`と`30`を受け取り、足し算をすると決まっているなら、普通のPython関数で十分です。「15と30を合わせるといくつ？」という文章が入力なら、モデルに意味を読み取らせ、足し算を選ばせることもできます。「パーティーの音楽を探して」なら、モデルが検索を選び、返された情報を使えます。

フレームワークは流れを整理しますが、正しい回答を保証するものではありません。ツールが実際に動いたか、回答がその結果に基づいているかを確認しましょう。

## アクションを依頼する2つの方法 { #agent-types }

- **CodeAgent：**モデルがPythonコードを提案し、実行エンジンがそれを動かします。
- **ToolCallingAgent：**モデルが構造化データでツールを指定し、フレームワークが読み取って関数を呼びます。

どちらも**アクション → 観測結果 → 次のアクションまたは最終回答**という流れを取れます。2つの形式はステップ10で詳しく見ます。

[![コードとJSONによるアクションの比較](images/huggingface/code_vs_json_actions.png)](images/huggingface/code_vs_json_actions.png)

??? info "この図の説明を読む"

    **同じスマートフォンを、どの国で買うと最も安いか**を調べる例です。米国、日本、ドイツ、インドについて、為替、税、商品価格、送料を使い、最終的な金額を比べます。

    **左側（Text/JSON）：**為替を調べる、価格を調べる、換算する、といった操作を個別の依頼として表しています。`Environment`は実行側から返る値です。

    **右側（Code）：**`for`ループで各国の処理を繰り返し、変数に結果を保存して、`min(...)`で最安の国を選びます。複数の操作を1つのコードブロックにまとめられる点を示しています。

    どちらも、実際のデータを返すツールと、それを動かす実行側が必要です。図の金額は説明用の例で、現在の価格ではありません。また、すべての仕事で右側の手順が必ず少なくなるという意味ではありません。

## どこで動くのか { #model-integration }

今週のプログラムは、配布された`week03_common.py`の`build_model()`でGroqに接続します。第2週と同じGroqキーを使います。LLMはリモートで動くので、問い合わせにはインターネット接続が必要です。

CodeAgentとツールは自分のPCで動きます。smolagentsをインストールしても、LLM本体がPCに入るわけではありません。メニュー選択のようなPythonツールはGroqなしで直接呼べますが、エージェントにツールを選ばせて使うときはモデルが関わります。
