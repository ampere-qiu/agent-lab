# 第05週 · まとめと完了確認 { #week-5-completion }

**目標：**文書、ツール、エージェント、ワークフローの接続を、PCで得た実際の結果で示します。作業中の`week05-exercises`と`evidence.md`を開いてください。

## 作ったものを振り返る { #review }

HF Unit 2.2の順に、連携機能を探し、文書のクエリエンジンを組み、関数と検索をツールにし、会話の記憶や受け渡しを持つエージェントを動かしました。さらに、イベントと共有状態で処理をつなぎました。検索は文章を供給し、ツールは処理を行い、モデルは判断や回答生成を担当し、イベントはステップを接続します。この境界を説明してください。

## 必要な記録 { #evidence }

| 話題 | 開くファイル | 示す内容 |
| --- | --- | --- |
| 連携 | `my_llm.py` | 成功したあいさつ、または実際に起きた接続失敗。 |
| コンポーネント | `my_ingest.py`、`my_retrieve.py`、`my_query.py` | 文書10件、保存したベクトル、実際に取り出した文章、照合した回答。 |
| ツール | `my_tools.py`、`my_query_tool.py`、`my_toolspec.py` | 関数と検索ツールの直接実行、名前・説明、補助ツールの方法の説明。 |
| エージェント | `my_agent.py`、`my_memory.py`、`my_rag_agent.py`、`my_agent_team.py` | 計算の実行、Bobの比較、ツール選択、元のEXCERPT／SOURCEの確認、受け渡し後の調査。 |
| ワークフロー | `my_workflow.py`、`my_workflow_steps.py`、`my_workflow_loop.py`、`my_workflow_draw.py`、`my_workflow_state.py`、`my_team_workflow.py` | あいさつ、イベントのデータ、制限付きループ、`flow.html`、保存した質問、計算カウンター。 |
| 理解 | `evidence.md` | 小テスト1・2の答えと、モデルを使う各結果の限界を1つずつ。 |

`my_evaluate.py`は任意の忠実性評価です。Gmail、MCPサーバー、Phoenixの外部連携は読み物の発展内容で、接続は必須ではありません。何のための仕組みかをメモに残します。

比較で変えた行を元へ戻し、各ページ末尾の一覧を確認します。各行に**完了**または**未完了**と、観測した結果か未解決の失敗を短く書いてください。必要なツール記録がない回答、GENERATED ANSWERを元のEXCERPTとして引用した回答、共有ContextがBobを忘れる結果は、該当項目の完了にはなりません。成功を作り上げず、確認できた未完了を残します。

## 再実行せずに説明する { #explain }

1. PC上の埋め込みモデルを使う処理と、Groqを使う処理はどれですか？
2. どの出典が回答を支えると、どう判断しましたか？
3. 自分で検索ツールを直接呼ぶ場合と、エージェントに選ばせる場合で何が変わりましたか？
4. ワークフローのステップは何でつながり、共有状態はどこにありましたか？
5. 計算の呼び出し回数、モデルへの問い合わせ回数、エージェント数が別の数なのはなぜですか？

各答えで該当コードと保存した観測結果を1つ示します。キーは記録へ含めません。生成したデータベース、自作ファイル、メモを一緒に残してください。Webサイトは進み具合を保存したり、結果を認定したりしません。
