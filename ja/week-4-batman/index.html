    15 · マルチエージェントシステム¶

    参考：Hugging Face Multi-Agent Systems。矢印をたどり、下へ渡る依頼と、上へ返る根拠を確認してください。

    目標：エージェントの役割と委任を理解し、Batman調査チームを作ります。

    まずPart Aでエージェントの連携を学び、Part BでBatmanチームを作ります。3体目の追加は任意です。

    Part A · マルチエージェントの仕組み¶

    この図の説明を読む

    管理役がタスクを受け、必要な作業をコードツールやWeb調査役へ渡す構成です。管理役から下向きの矢印は依頼、調査役から戻る矢印は調査結果を表します。Web調査役は自分で検索やページ閲覧を選ぶループを持ちます。コードツールの呼び出しは、それ自体がもう1体のエージェントになるわけではありません。結果が管理役へ戻るとき、出典や不確かな点も一緒に渡す必要があります。図をクリックすると拡大できます。

    Hugging Faceの図を変更せず使用しています。元の大きさで開く。

    1. マルチエージェントとは？¶

    エージェントは、モデルが判断するループ、指示、ツール、自分の実行履歴を持ちます。マルチエージェントシステムは、このようなエージェントを2体以上つなぎ、作業を分担して結果を受け渡す仕組みです。役割（role）は担当する仕事、受け渡し（handoff）はエージェント間で渡す依頼と情報です。

    1体のCodeAgentでも検索、ページ閲覧、計算、レポート作成はできます。履歴が1つなので、動きを追いやすい利点があります。ただし、長い調査では検索の抜粋、ページ本文、計算結果、レポートの判断が同じ履歴にたまります。不要な詳細に注意を取られ、同じ検索を繰り返したり、後で必要な出典を見失ったりすることがあります。

    管理役と専門役に分けると、調査側に独自の「モデル → アクション → 観測」のループができます。管理役が目標を渡し、専門役が検索語や読むページを選び、短い報告を返します。管理役はその報告を使って続きを進めます。決められたPython処理を実行して値を返す関数ツールとは、この点が異なります。

    2体で同じモデル接続とキーを共有しても、履歴や使えるツールは別々です。また、2体いるからといって並列実行になるとは限りません。この演習では管理役が専門役の返答を待ちます。受け渡しで管理役の履歴を整理できる一方、大事な根拠が失われる可能性もあります。問い合わせと連携が増えると、時間や費用が増えることもあります。チームのほうが良いと決めつけず、実際の記録で評価してください。

    この図の説明を読む

    左の1 · MANAGERが全体を管理する役、右の2 · SPECIALISTが特定の仕事を担当する役です。それぞれに「Model → action → observation」という独立したループがあります。上の右向きの矢印Requestは依頼、下の左向きの矢印Evidenceは返された根拠です。専門役の下のTOOLSは検索やページ閲覧などの処理で、追加のエージェントには数えません。この図のエージェントは合計2体です。

    教材の図：別々のループを持つ2体のエージェントです。ツールは追加のエージェントではありません。図を拡大する。

    例に進む前の確認¶

    1. 管理役が1体の調査役に委任し、計算ツールも呼びます。エージェントは何体ですか？

    確認1 — ループを数える

    管理役と調査役の2体です。計算ツールは定められた処理を行うもので、3体目のモデル判断ループではありません。

    2. 2体で1つのモデル接続を共有すると、同じエージェントになりますか？

    確認2 — 接続とエージェントの違い

    なりません。別々のエージェントとして、それぞれの履歴、指示、使えるツールを持ちます。役割ごとに別のモデルを用意する必要はありません。

    3. 管理役と専門役の図があれば、並列実行や回答の検証ができていると言えますか？

    確認3 — 実行を調べる

    言えません。この演習では管理役が専門役を待ちます。実際の委任と返された出典を確認してください。図やエージェントの追加だけでは正しさを保証できません。

    Part B · メイン演習：Batman調査チーム¶

    課題：Web調査役と管理役を作り、地点の調査、出典の確認、レポートの作成を連携して行わせます。

    アルフレッドは、代わりのバットモービルが見つかりそうな場所の候補を必要としています。Batmanの撮影地3か所とスーパーカーメーカーの工場1か所を調べ、その用途と座標の根拠を残してください。架空のゴッサムまでの貨物航空輸送時間を授業用の式で概算し、出典付きの表と色分けした座標図を作ります。

    最初に調査ツールを確認します。その後、専門役と管理役を作ってつなぎ、1件の撮影情報を確認してから4地点へ進みます。各確認問題に答え、結果をevidence.mdに残してください。

    始める前に：第04週の準備と、記録用のevidence.md、evidence-filesの作成を終えます。この演習の回答と結果は、メモのTopic 15に記入します。

    ファイル 配布・作成・生成の区別
    week04_common.py、week04_search.py、week04_tools.py ZIPに入っています。指定されたときに既存のファイルを開きます。作り直す必要はありません。
    my_batman_tools.py、my_batman.py 手順3、4に沿ってweek04-exercises内に作ります。
    my_batman_verified.py 配布されません。任意課題に取り組むときだけ、動作しているチームのコピーを作ります。
    evidence.md 準備で作成したファイルです。回答とターミナルの抜粋を保存します。
    outputs/batman-report.html レポートツールが成功したときに生成されます。空のHTMLファイルを自分で作らないでください。

    すべて、環境を有効にした同じweek04-exercisesのターミナルで実行します。調査やモデルの記録はターミナルで読み、生成したレポートだけをブラウザで開きます。

    必須の2体と任意の追加を確認する¶

    この図の説明を読む

    1 · MANAGERが管理役で、調査を依頼し、出典と不足情報を保ちながらcargo_timeとsave_reportを使います。最終レポートと地図を書くのはこの役だけです。左下の2 · WEB SPECIALISTが調査役で、撮影地3か所と工場1か所の候補、用途と座標の出典を調べます。この管理役＋Web調査役の2体が必須です。

    右下の点線の枠3 · VERIFIER · OPTIONALが任意の検証役です。追加すると合計3体になります。引用されたページを独立して読み、pass、fail、uncertainと根拠を返します。点線は追加した場合の依頼と判定の受け渡しです。調査役と検証役はどちらも管理役へ直接報告します。ツールは各枠の中に書かれており、エージェントの人数には含めません。

    教材の図：必須は管理役＋Web調査役の2体、任意で検証役を加えると合計3体です。図を拡大する。

    Web調査役が調べ、管理役が全体の調整、計算、保存を行います。任意課題では、調査結果1件を独立して確認し判定する検証役を加えます。検証役は調査役の別名ではなく、別のエージェントです。検索・ページ閲覧・計算・レポートの各ツールは、人数を増やすものではありません。

    コードを書く前に：専門役が「Wollaton Hallは良い候補です」としか返さなかったら、管理役は何を確かめられるでしょうか？地図の作成と出典の確認には、どの情報が必要ですか？

    考え方を確認する

    裏付けるページ、座標とその出典、撮影地か工場かという区分、不確かな点が足りません。説得力のある要約だけでは調査記録として使えません。専門役の自信だけから、管理役が不足した根拠を復元することはできません。

    2. 各エージェントの役割を理解する¶

    下の表で担当を確認します。コードを書く前に、2つの役割を自分の言葉でevidence.mdのTopic 15に説明してください。

    部分 渡すもの・担当すること
    Web調査役 WebSearchTool(budget=budget)とPageExcerptTool(budget=budget)、呼び出し名web_specialist、調査の役割を伝える説明文。
    管理役 cargo_timeとsave_report。managed_agents=[specialist]で調査役へ委任できます。
    受け渡し 裏付けのある地点と用途、確認できた場合の座標、用途の出典URL、座標の出典URL、根拠と不確かな点。
    小さなテスト ONE_LOCATION_TASKが建物1件の情報と出典を求めます。レポートは保存しません。
    全体のタスク TASKが異なる撮影地3か所と工場1か所、計算、表・座標図の保存を求めます。

    レポートの1行に必要な項目はlocation、kind（filmingまたはfactory）、latitude、longitude、source_url、coordinate_source_url、evidenceです。撮影情報の出典だけでは、座標を確認できない場合もあります。不足している根拠は不足として示し、計算用の座標を推測で作らないでください。

    Given task → manager → web_specialist(task="a research goal")
                           ↓ web_search → visit_webpage
                     sourced report → manager
                           ↓ cargo_time → save_report (full task only)
                     outputs/batman-report.html

    1. 調査役に検索・ページ閲覧ツールを持たせ、管理役に計算・レポートツールを持たせるのはなぜですか？

    解答1 — それぞれの担当

    調査役は自分のループで根拠を集めます。管理役はその調査を依頼し、返された座標で計算して保存します。管理役が直接検索できないため、委任の動きが分かりやすくなります。

    2. 専門役が返答に出典URLと不確かな点を含めるべきなのはなぜですか？

    解答2 — 使える根拠

    自分と管理役が、各主張と座標の裏付けを確認するためです。根拠のない結論では計算や点検を支えられません。足りない項目は解決するまで不足として残します。

    3. ツールと概算式を確認する¶

    目標：エージェントに使わせる前に、LLMなしでツールを試します。

    1. エディターでweek04-exercisesを開き、requirements.txtとweek04_common.pyを確認します。
    2. ファイル → 新しいテキストファイル → 名前を付けて保存で、同じ場所にmy_batman_tools.pyを作ります。ZIPには入っていないので、ここで作成してください。
    3. 下のコード全体を貼り付け、WindowsはCtrl + S、MacはCommand + Sで保存します。
    4. 拡張子が.pyで、.py.txtではないことを確認します。.venv、lessons、assetsの中には保存しません。

    まずコード内の検索語とURLを使い、それぞれの戻り値を読みます。ページを取得できない場合はエラーを記録し、自分のブラウザでも出典を確認してください。

    このファイルの役割 — my_batman_tools.py：ウェブ検索、1ページの読み込み、固定座標による計算ツールの確認を行います。LLMは使いません。ターミナルの出力と出典ページを調べます。

    my_batman_tools.py
    from week04_search import WebSearchTool, PageExcerptTool
from week04_tools import cargo_time

print("Same-coordinate classroom estimate:", cargo_time(40.7128, -74.0060))
print(WebSearchTool()("Batman Wollaton Hall filming official"))
print(PageExcerptTool()("https://wollatonhall.org.uk/hall-and-museum/history/", focus="Wayne Manor Batman"))
    コードの説明を読む
    コード 意味
    from ... import ... 配布された上限付きの検索・ページ閲覧クラスと計算ツールを読み込みます。
    cargo_time(40.7128, -74.0060) ゴッサムと同じ座標を直接計算します。モデルは使いません。
    WebSearchTool()("...") ツールを作って検索語を渡し、検索サービスから抜粋とURLを取得します。
    PageExcerptTool()("...", focus="...") 最大1,600文字の関連するページ抜粋を取得します。Chromeを操作する処理ではありません。

    検索結果は出典を探す手掛かりです。ブラウザで出典を開き、抜粋が主張を裏付けるか確認してください。出力上限は維持します。抜粋はページの一部なので、確認できない点はメモに残します。

    実行：python my_batman_tools.py。確認すること：同じ座標の概算が1.0になり、検索にURLが返り、ページ閲覧では文章か明確なエラーが返ることです。evidence.mdに検索結果のURLを1つと、主張を裏付けるか判断できる文章を残します。取得を拒否された場合は失敗として記録し、別の信頼できる出典を確認します。

    配布されたweek04_tools.pyを開き、cargo_timeを探します。次へ進む前に関数を読んでください。自分のプログラムではこの関数をインポートします。式はround(distance_km * 1.1 / 750 + 1, 2)です。架空のゴッサム(40.7128, -74.0060)からの大圏距離に10%を加え、750 km/hで割り、固定の1時間を加えています。授業用の貨物航空輸送の概算で、実際の運航予定ではありません。緯度と経度を受け取って時間を返す関数であり、座標の検索や撮影地の確認はしません。

    計算の確認：同じ座標でもゼロではなく1.0になるのはなぜですか？速度の仮定を下げたら時間は増えますか、減りますか？仮定した値と、出典が必要な値を分けて説明してください。

    概算を確認する

    距離がゼロでも固定の1時間が残ります。速度を下げると距離÷速度が大きくなります。座標は出典で裏付ける入力で、速度、距離の割増、固定時間は授業用の仮定です。計算が正しくても、撮影地という主張が正しいとは限りません。

    4. エージェントを1体ずつ作る¶

    目標：Web調査役と管理役を作り、管理役が調査を委任できるようにつなぎます。

    1. エディターでweek04-exercisesを開き、requirements.txtとweek04_common.pyを確認します。
    2. ファイル → 新しいテキストファイル → 名前を付けて保存で、同じ場所にmy_batman.pyを作ります。このファイルはZIPにはありません。
    3. 同じファイルに4A → 4B → 4C → 4Dの順で追加します。各ブロックは前の内容の下へ貼り付け、既存部分を置き換えたりインポートを重複させたりしません。字下げは表示どおりに保ちます。
    4. 各段階でCtrl + SまたはCommand + Sで保存します。拡張子は.pyです。4Dが終わるまでは実行しません。それ以前はオブジェクトの作成だけで、実行するタスクがまだありません。
    5. 古いmy_batman.pyがある場合は結果を保存してから内容を一度消し、手順どおりに作り直します。古い完成コードの下に追加しないでください。

    このファイルの役割 — my_batman.py：自分で作る2体のエージェントを、Groqとウェブ調査ツールで動かします。管理役が調査を頼み、その結果を使ってローカルの計算・レポートツールを呼びます。最初の小さなタスクはターミナルに受け渡しを表示し、後の全体タスクではoutputs/batman-report.htmlを生成できます。

    4A. インポートとモデル接続を用意する¶

    最初に次のブロックを貼り付けます。インポートだけではエージェントは作られません。

    my_batman.py
    from smolagents import CodeAgent
from week04_common import build_model, agent_options, run_task
from week04_search import WebSearchTool, PageExcerptTool, ResearchBudget
from week04_tools import cargo_time, save_report

model = build_model(max_tokens=800)
    4Aの説明 — 接続を共有する

    CodeAgentはこの後2回使うクラスです。ほかのインポートは接続・検索・計算・レポート用の補助機能を読み込みます。build_model(max_tokens=800)は出力の上限を小さくしたGroq接続を準備し、ファイル実行時に必要ならキーを求めます。ここでは検索もエージェントの作成もしません。接続を共有しても履歴は別です。

    確認A：この時点でエージェントを何体作りましたか？

    解答A

    0体です。クラスのインポートやモデル接続の準備は、CodeAgent(...)の呼び出しではありません。

    4B. Web調査役を作る¶

    model = build_model(max_tokens=800)の下に追加します。これが最初のエージェントです。次へ進む前に、名前、役割の説明、モデル、ツールを自分のファイルで示してください。

    my_batman.py
    budget = ResearchBudget(max_searches=1, max_pages=2)
specialist = CodeAgent(
    tools=[WebSearchTool(budget=budget), PageExcerptTool(budget=budget)],
    model=model,
    name="web_specialist",
    description="Researches ONE named place per call. Visit sources and return a concise claim, URL and quote. Seek coordinates only when explicitly requested. Respect tool limits; stop after sufficient evidence or mark gaps. Return at most 500 characters.",
    **agent_options(max_steps=4, compact=True),
)
budget.bind(specialist)
    4Bの説明 — 専門役を作る
    設定 意味
    specialist = CodeAgent(...) 別個のエージェントを作り、変数specialistに保持します。
    budget = ResearchBudget(max_searches=1, max_pages=2) 1タスクにつき検索1回、ページ取得2回までとします。失敗や拒否も数え、同じURLの再試行は拒否します。
    tools=[WebSearchTool(budget=budget), PageExcerptTool(budget=budget)] 2つのツールで同じ回数制限を共有します。検索は最大2件の短い結果、ページ閲覧は最大1,600文字の関連する抜粋を返します。
    model=model 4Aのモデル接続を渡します。

    サービスがリクエストを拒否した場合¶

    検証役独自のname、description、CodeAgentを用意します。既存の専門役を別の変数へ代入するだけでは、新しいループにはなりません。

    ヒント2 — 新しい役をつなぐ

    コピーの管理役にmanaged_agents=[specialist, verifier]を使います。検証役専用のResearchBudget(max_searches=1, max_pages=2)、上限付きの検索・ページツール、最大4ステップを与え、その予算を検証役へbindします。調査役とカウンターを共有せず、レポートツールも与えません。1回につき1件を確認して、短い判定を返します。

    ヒント3 — 実際の検証を依頼する

    登録だけでは実行されません。管理役が出典付きの1件を渡して判定を求めるようタスクを変更します。failやuncertainの扱いを定め、この任意課題では新しいレポートを保存しません。

    検証役の解答1 — 名前・担当・ツール

    用途と座標を独立して確認する役が適切です。独自の名前と検索・ページ閲覧ツールを持たせ、調査役の自信ではなく引用先を調べさせます。

    検証役の解答2 — 役に立つ判定

    各主張についてpass／fail／uncertain、確認したURL、根拠、修正点または不足項目を返します。実際に確認した出典がなければ、単に別の主張を増やすだけです。

    検証役の解答3 — いつ記録を受け入れるか

    調査後、記録を受け入れる前に検証役を呼びます。根拠付きの判定か、不確かな理由を返し、予算を使い切った後に修正のループを続けません。このテストは既存レポートを変更しません。後で検証済みのレポートを作る場合も、書くのは管理役です。

    検証役の解答4 — 構成と実行

    図には管理役と異なる2体の専門役が必要です。そのうえで、実行記録に両方の呼び出しがあるか確認します。図だけでは実行した証拠になりません。

    検証役の解答5 — 意図的な誤り

    建物の撮影・歴史ページは、スーパーカー工場という主張を裏付けません。ページを読んだ検証役は否定するか、裏付けなし／不確かと判定するはずです。見逃したら実際の結果を残します。その後、通常の1件のタスクに戻して判定を比べます。エージェントを増やしても、有効な修正を保証するわけではありません。

    任意課題で示すこと

    図に3体目があるだけでは不十分です。追加した役、2つ目の委任、ページの観測、根拠付きの判定を示してください。検証役も誤ることがあるため、出典は自分でも確かめます。

    コードを振り返る¶

    4Bで専門役、4Cで管理役を作りました。ファイル内でそれぞれを作る場所と、managed_agents=[specialist]でつなぐ場所を探してください。手順6では短い抜粋と新しい専門役の履歴を保ったまま、全体タスクへ切り替えました。任意の検証役を加えた版と比較できるよう、2体版も残します。
