    22 · エージェントにツールを選ばせる¶

    目標：ツールを直接呼ぶ場合と、モデルが行動を選ぶ場合の違いを確認します。小テスト1を終え、同じ有効なweek05-exercisesのターミナルを使ってください。

    1. エージェントの方式を選ぶ¶

    HFは、構造化されたツール呼び出しを使う関数呼び出し型、文章形式の推論・アクションを解釈するReAct型、専用の動作を定義する独自エージェントを紹介しています。ここでは授業用モデルで関数呼び出し型を使います。AgentWorkflow.from_tools_or_functionsは、モデルのメタデータに応じて対応する方式を選びます。

    この図の説明を読む

    3つのカードは、判断のループを作る方式の違いです。関数呼び出し型は、モデルから構造化されたツール名と入力を受け取ります。ReAct型は文章のアクション形式を解釈し、独自型は専用の動作を定めます。モデルがその形式に従えることも必要です。この演習の「2 times 2」では、モデルがmultiplyとa=2, b=2を選び、Pythonが4を計算し、モデルが答えます。実行記録で順に確かめましょう。

    HFの図を変更せず使用しています。原典のレッスン · 図を拡大する。

    エージェントもツールや入力を間違えることがあります。ヘルパーが表示するREQUESTは依頼、TOOLは実際の呼び出し、RETURNは戻り値、ANSWERは最終回答です。回答だけで判断せず、この観測結果を確認します。モデル内部の非公開の思考過程を表示する課題ではありません。

    2. 計算ツール1つから始める¶

    my_agent.pyを作成します。掛け算の関数を渡し、HFの「2 times 2」という質問で、呼び出しと回答を表示します。Groqが行動を選び、Pythonが計算します。Groqのトークンを使い、結果はターミナルに出ます。

    my_agent.py
    from llama_index.core.agent.workflow import AgentWorkflow
from week05_common import get_llm, run, show_agent


def multiply(a: int, b: int) -> int:
    """Multiply two integers and return the result."""
    return a * b


async def main():
    agent = AgentWorkflow.from_tools_or_functions(
        tools_or_functions=[multiply], llm=get_llm(),
        system_prompt="Use the multiply tool for multiplication. State its returned result.",
        timeout=180,
    )
    await show_agent(agent, "What is 2 times 2? Use the tool.")

if __name__ == "__main__":
    run(main)
    エージェントの説明を読む

    関数の引数・型・docstringからツールの窓口を作ります。AgentWorkflow.from_tools_or_functionsはツール、モデル、指示をまとめます。show_agentが開始し、完了したツール呼び出しを表示します。反復回数とタイムアウトが実行を制限します。mainガードがあるので、ほかのプログラムからmultiplyを読み込んでも、この依頼は実行されません。

    実行：python my_agent.py。

    multiplyにa=2、b=2が渡り、戻り値が4で、回答も一致することを確認します。ツール呼び出しがなければ、答えが4でもツール利用は未確認です。前のweather.call(...)と比べ、どちらの場合に誰が操作を選んだか説明してください。

    3. Contextで会話を覚える¶

    my_memory.pyを作成します。「My name is Bob.」と伝え、同じContextで名前を聞き、その後、新しいContextでも同じ質問をします。3つのメッセージを入力とし、比較結果はターミナルに出ます。3回ともGroqのトークンを使います。

    my_memory.py
    from llama_index.core.agent.workflow import AgentWorkflow
from llama_index.core.workflow import Context
from my_agent import multiply
from week05_common import get_llm, run, show_agent

async def main():
    agent = AgentWorkflow.from_tools_or_functions(
        tools_or_functions=[multiply], llm=get_llm(), timeout=180,
        system_prompt="Answer briefly. Remember only information present in this conversation.",
    )
    ctx = Context(agent)
    await show_agent(agent, "My name is Bob.", ctx=ctx)
    await show_agent(agent, "What was my name again?", ctx=ctx)
    print("NOW A FRESH CONTEXT:")
    await show_agent(agent, "What was my name again?", ctx=Context(agent))

if __name__ == "__main__":
    run(main)
    会話の記憶の説明を読む

    Context(agent)は実行履歴の情報を持ちます。同じctxを渡すことで最初の2つの会話をつなぎます。配布ヘルパーのshow_agentは、以前の会話を次の実行へ明示的に渡します。新しいContextには先ほどの名前は渡りません。同じモデルオブジェクトを使うだけでは、履歴は共有されません。プログラムを再起動した後まで記憶を保存する例でもありません。

    予測：先ほどの名前を使えるのはどの質問でしょうか？実行：python my_memory.pyを1回実行します。

    3つの回答を確認してください。

    1. 最初はBobという名前を受け取る。あいさつの文面は変わっても構いません。
    2. 同じContextはBobを覚えている。
    3. 新しいContextは名前が分からないと答える。

    UnserializableKeyWarningが出る場合：フレームワークは記憶用オブジェクトを自動で保存形式に変換できません。ヘルパーが次の実行へそのオブジェクトを渡すので、上の回答で確認します。2番目がBobを忘れる場合は、python week05_common.pyで2026-11-10.2を確認してください。違う場合は現在のZIPのヘルパーだけを入れ直し、この演習を再実行します。ほかの作業は残してください。

    最終回答の表示方法を読む

    モデルが<think>のタグや、</think>前後で重複する文章を返すことがあります。ヘルパーはタグ付きの思考部分を表示せず、最終回答の文章を表示します。表示を整える処理なので、回答の根拠は引き続きツールと出典で確認します。

    3つの結果をevidence.mdの22の欄に記録します。プログラムを起動し直すと例はリセットされます。配布されたBobのメッセージは変えずに使ってください。

    4. エージェントにRAGツールを渡す¶

    この図の説明を読む

    エージェントには複数の行動候補があり、文書検索もその1つです。ツールを選び、結果を読んで、どう答えるか決めます。この演習で使えるのはpersonasとmultiplyです。図のWeb検索や外部APIは、より広い構成の例です。人物像の質問にはpersonas、掛け算にはmultiplyを使うか、選択と戻り値で確認します。

    HFの図を変更せず使用しています。原典のレッスン · 図を拡大する。

    my_rag_agent.pyを作成します。掛け算と人物像の検索ツールを渡し、説明文の検索と根拠の返答を依頼します。クエリエンジンもエージェントもGroqを使うため、ツール1回でモデルを複数回呼ぶ場合があります。ターミナルの実行記録と最終回答を読みます。

    my_rag_agent.py
    from llama_index.core.agent.workflow import AgentWorkflow
from my_agent import multiply
from week05_common import get_llm, run, show_agent
from week05_rag import persona_tool

async def main():
    llm = get_llm()
    agent = AgentWorkflow.from_tools_or_functions(
        tools_or_functions=[multiply, persona_tool(llm)], llm=llm, timeout=180,
        system_prompt=("Use personas for questions about profiles and multiply for arithmetic. "
                       "Quote only original EXCERPT text, cite its SOURCE filename, and distinguish it from GENERATED ANSWER text. "
                       "Search results cover only retrieved passages. Say no match was found in those passages; do not claim all profiles were checked. Do not invent names or contact details."),
    )
    await show_agent(agent, "Find the persona interested in Cincinnati art. Use personas and quote its description.")

if __name__ == "__main__":
    run(main)
    エージェントによるRAGの説明を読む

    決められたクエリエンジンは毎回同じ検索・回答の経路を進みます。このエージェントはツールとpersonasへの質問を選べます。クエリエンジンの回答を観測結果として受け、さらに回答を作る場合があります。どちらにも根拠のない追加がないか調べます。return_direct=Falseにより、ツールの戻り値を即座に最終回答とせず、エージェントが使えます。

    実行：python my_rag_agent.py。

    次の順に確認します。

    1. TOOL: personasと、返されたSOURCE、EXCERPTを探す。
    2. data内の出典ファイルを開き、本文と抜粋を照合する。
    3. 最終回答の引用が元の本文に一致し、ファイル名を示しているか確認する。

    GENERATED ANSWERはモデルの要約です。呼び出し、元の文章、出典表示のどれかが足りなければ、不足を記録します。

    my_rag_agent.pyで選択を比較します。mainの中のawait show_agent(...)を探してください。末尾のrun(main)はそのままにし、依頼の1行全体を次へ置き換えます。先頭の空白4個を残します。

        await show_agent(agent, "What is 2 times 2? Use multiply.")

    保存し、python my_rag_agent.pyを1回実行します。人物像の検索ではなく、TOOL: multiplyとRETURN: 4を確認してください。記録をevidence.mdへ残したら、次の元の行へ戻して保存します。

        await show_agent(agent, "Find the persona interested in Cincinnati art. Use personas and quote its description.")
    任意：別の関心について検索する

    利用可能な範囲で行うHFとの比較です。元の依頼をevidence.mdへ控え、同じmain内で次の1行を使ってください。

        await show_agent(agent, "Search the database for 'science fiction' and return some persona descriptions. Use only the source excerpts. If they contain no match, say no match was found in the retrieved passages; do not claim to have checked every profile.")

    python my_rag_agent.pyを1回実行します。ツールが取り出すのは10ファイルのうち最大2つの文章です。どちらにもSFへの関心が書かれていなければ、「この検索結果には一致なし」と言えます。「データベース内の誰もSFを好まない」は、残りを全部確認していないため言い過ぎです。回答がどちらの主張か記録し、上に示した元の依頼へ戻します。

    5. 2体のエージェントをつなぐ¶

    HFは次に計算役と情報検索役を作ります。それぞれに専用のツールと指示があります。AgentWorkflowの最初に受け取る役（root agent）が依頼を受け、受け渡し（handoff）で別の役へ移ります。図だけでなく実行記録で確認してください。

    my_agent_team.pyを作成します。計算役から始め、info_lookupが担当する人物像の調査を依頼します。既存のインデックス、共有するGroq接続、モデルのトークンを使います。最終回答だけでなく、受け渡しと検索をターミナルで確認します。

    my_agent_team.py
    from llama_index.core.agent.workflow import AgentWorkflow, FunctionAgent
from my_agent import multiply
from week05_common import get_llm, run, show_agent
from week05_rag import persona_tool

async def main():
    llm = get_llm()
    calculator = FunctionAgent(
        name="calculator", description="Multiplies integers.",
        system_prompt="Use multiply for math. Hand persona research to info_lookup.",
        tools=[multiply], llm=llm, can_handoff_to=["info_lookup"],
    )
    researcher = FunctionAgent(
        name="info_lookup", description="Searches ten persona descriptions.",
        system_prompt="Use personas. Quote only original EXCERPT text and cite its SOURCE filename. GENERATED ANSWER is not a source quotation. Limit missing-match claims to the retrieved passages. Mark missing information.",
        tools=[persona_tool(llm)], llm=llm, can_handoff_to=["calculator"],
    )
    team = AgentWorkflow(agents=[calculator, researcher], root_agent="calculator", timeout=180)
    await show_agent(team, "Find the Cincinnati art historian. Hand this task to info_lookup, which must query personas.")

if __name__ == "__main__":
    run(main)
    チームの説明を読む

    2つのFunctionAgentは名前、ツール、指示が異なります。can_handoff_toが渡せる相手を定め、root_agent="calculator"が最初の役を選びます。同じモデル接続を使っても別の役です。記録では受け渡しの後にpersonasが出るはずです。HFの単純な計算問題は計算役だけで処理できますが、ここでは調査を依頼して接続を確かめます。

    実行：python my_agent_team.py。info_lookupへの受け渡し、その役のpersonas呼び出し、元の文章、それに沿う回答を探します。実際の受け渡しと結果を22の欄へ記録してください。

    確認メモ：計算、Bobの比較、RAGツールの選択、受け渡しの記録を残します。1つのモデル接続を共有する2体が、なぜ別々のエージェントなのか説明してください。
