    第05週 · LlamaIndex¶

    目標：文書を検索し、ツールを使い、明確な手順で仕事を受け渡すアシスタントを作ります。

    先に第4週を終えてください。今週はHF Unit 2.2と同じ順序で学びます。以前の作業を残し、新しいweek05-exercisesフォルダー、Python 3.11、エディター、ターミナルを使います。ノートブックやGPUは不要です。英語版と日本語版は、同じコードと演習を使います。

    学習の順番¶

    順番 レッスン 行うこと
    準備 このページ 専用の環境を作り、人物像の説明文10件を取得する。
    18 入門 コンポーネント、ツール、エージェント、ワークフローを区別する。
    19 LlamaHub パッケージとimportを対応させ、モデル接続を試す。
    20 コンポーネント 読み込み、分割、埋め込み、保存、検索、質問と根拠の確認。
    21 ツール 関数ツール、検索ツール、ローカルのツールの集まりを作る。
    確認 小テスト1 エージェントを作る前に、部品とツールを説明する。
    22 エージェント 計算、Bobの記憶、人物像の検索、仕事の受け渡し。
    23 ワークフロー イベントとステップ、制限付きループ、作図、状態の共有。
    確認 小テスト2 判断、イベント、記憶、共有状態を説明する。
    振り返り まとめと完了確認 作成ファイルを示し、実際の結果を説明する。

    人物像の検索、練習用の天気、計算、Bobの会話、ワークフローはHFの単元に沿っています。保存したPythonファイルとしてPCで実行します。これまでの授業用Groq接続を使うので、新しいモデル提供元のアカウントは不要です。

    1. ZIPを展開してフォルダーを開く¶

    第5週の英語・日本語スターターをダウンロード

    1. ZIPを保存します。Windowsは右クリックしてすべて展開、MacはFinderでダブルクリックします。
    2. 展開先で、requirements.txtとweek05_common.pyが入っているフォルダーを探します。Macでは通常、展開されたweek05-exercises自体です。Windowsではその外にもう1つフォルダーがある場合があります。ファイルが入ったほうをagent-course内の以前の演習フォルダーの隣へ移し、名前をweek05-exercisesにします。
    3. VS Codeのファイル → フォルダーを開くでweek05-exercisesを開きます。requirements.txt、prepare_personas.py、week05_common.py、week05_rag.pyが同じ場所にあることを確認します。
    4. 配布ヘルパーは残します。my_*.pyはZIPに入っていません。各レッスンのコードを使い、ヘルパーの隣に自分で作成します。Web版、またはlessons/enとlessons/jaのMarkdownを読んで進めてください。
    配布ファイル 用途
    requirements.txt smolagentsとは分けた第5週用のパッケージ。
    prepare_personas.py LLMを使わず、公開された人物像10件を取得する。
    week05_common.py 設定を読み、Groqへ接続し、ツールの結果を表示する。
    week05_rag.py 後の演習で保存済みのインデックスを再利用する。
    README.md、NOTICE.md、HF-LICENSE.txt 準備の要約、出典、ライセンス。
    lessons/en、lessons/ja 英語版と日本語版のレッスン。
    images/huggingface-week05 元のHFの図。クリックすると拡大できる。

    2. 専用の環境を作って有効にする¶

    対応するWindows／Macで64ビットのPython 3.11を使います。パッケージとモデル用の空き容量を確認してください。Macでの検証では環境だけで約1.6 GB使い、PCによって変わります。ローカル埋め込み用の大きなパッケージも含みます。インストール、人物像の取得、最初のモデル取得、Groqへの問い合わせには通信が必要です。取得後の検索や通常のワークフローはPCで動きます。有効にしたターミナルをそのまま使ってください。

    ターミナルを選び、Pythonを確認する¶

    WindowsのVS Code：［ターミナル → 新しいターミナル］を開きます。入力欄がPSで始まる場合はPowerShellです。ターミナルの＋の横の矢印 → Command Promptを選び、コマンドプロンプトを開いてください。以後も使う場合は、Ctrl + Shift + P → Terminal: Select Default Profile → Command Promptを選び、新しいターミナルを開きます。日本語表示では「ターミナル：既定のプロファイルの選択」を探します。下のコマンドはコマンドプロンプト用です。VS Codeの説明も参照できます。

    環境を作る前に確認します。

    • Windowsのコマンドプロンプト：py -3.11 --version。
    • Macのターミナル：python3.11 --version。

    Python 3.11.xと出たら先へ進みます。コマンドがない、または3.11が見つからない場合は、先に下を開いてください。

    Python 3.11が見つからない場合

    Windows 10／11：python.orgからPython install managerをインストールします。VS Codeを閉じて開き直し、新しいコマンドプロンプトで次を1行ずつ実行します。

    pymanager install 3.11
py -3.11 --version

    pymanagerは古いpyランチャーとの競合を避けるために使います。まだコマンドが見つからない場合はPythonのWindows向け対処を参照するか、実行したコマンドとエラーを教員へ伝えてください。

    Mac：Homebrewが入っていれば、次を実行します。

    brew install python@3.11
python3.11 --version

    brewがない場合はbrew.shの手順で導入し、インストーラーのNext stepsにあるターミナルの設定も行ってから、上の2行を実行します。HomebrewのPython 3.11のページで対応OSを確認できます。管理対象や非対応のPCでは、先へ進む前に教員へ相談してください。

    第5週のパッケージをインストールする¶

    Windows — コマンドプロンプト：1行ずつ実行します。

    cd /d "%USERPROFILE%\agent-course\week05-exercises"
py -3.11 -m venv .venv
.venv\Scripts\activate.bat
python --version
python -m pip install -r requirements.txt
python -m pip check
python week05_common.py
python prepare_personas.py

    Mac — ターミナル：1行ずつ実行します。

    cd ~/agent-course/week05-exercises
python3.11 -m venv .venv
source .venv/bin/activate
python --version
python -m pip install -r requirements.txt
python -m pip check
python week05_common.py
python prepare_personas.py

    保存場所が異なる場合は、自分のフォルダーのパスへ置き換えてください。(.venv)、Python 3.11.x、No broken requirements found.、Week 5 starter version: 2026-11-10.2、Saved 10 persona files in data/ (no LLM, no Groq tokens).を確認します。順に「環境が有効」「依存関係の不整合なし」「ヘルパーの版」「10件の保存完了」という意味です。版の確認はモデルを呼びません。取得時はdataset-source.jsonも生成します。data/persona_0.txtを開くと、シンシナティの美術史家の説明があるはずです。これは人物像の説明で、実在する人を特定した情報ではありません。不完全な説明も、推測で補わず使います。

    prepare_personas.pyはHFのノートブックと同じ人物像データの先頭10件を取得します。通常の取得先が失敗したり文章を省略したりする場合は、元のデータファイル約35 MBを取得・検証し、同じ10件の全文だけを保存します。HFのトークンは不要です。空でないdataを上書きしません。保存完了まで待ち、止まった場合は表示された原因に沿って対処してください。最初の埋め込みではBAAI/bge-small-en-v1.5をこのフォルダーの.cache/huggingfaceへ取得します。その後は完全なキャッシュをPCから読み、HFへ確認しません。CPUで動き、Groqのトークンは使いません。

    新しいターミナルでは、フォルダー移動と有効化の行だけを繰り返します。毎回環境を作り直す必要はありません。

    3. 自分のPC用の設定を作る¶

    第4週のキーを再利用する場合：GROQ_API_KEYの値だけを新しいファイルへコピーします。.env全体をコピーした場合は、GROQ_MODELを下の行へ置き換えてください。第4週のgroq/のような接頭辞は、今週のモデルIDには付けません。第4週のファイルは残します。

    エディターでweek05-exercisesの直下、week05_common.pyの隣に.envを作ります。.env.txtではなく.envとして保存し、次を貼ってキーの仮の値を置き換えます。

    GROQ_API_KEY=your_own_groq_api_key
GROQ_MODEL=qwen/qwen3.8-27b

    ヘルパーはload_dotenvを呼んでから設定を読みます。ファイルを作るだけではPythonは読み込みません。ターミナルに既にある環境変数が優先されます。以前このターミナルにGROQ_MODELを設定した場合は、Windowsのコマンドプロンプトでset GROQ_MODEL=、Macでunset GROQ_MODELとして消してから再実行します。キーはPCに残し、.envをGitHub、スクリーンショット、提出メモへ含めないでください。

    モデルはGroqのモデル一覧で2026-11-09に確認しています。プレビューモデルなので、失敗時は現在の提供状況と権限を確認してください。上のモデルIDを使います。ヘルパーは先頭のgroq/を取り除けますが、古いモデル名まで更新するわけではありません。この演習では依頼と検索した公開文章をGroqへ送ります。

    モデルを使うプログラムは1つずつ実行します。エージェントの反復は最大6回で、APIの自動再試行はありません。検索ツール1回で複数のモデル呼び出しが起きる場合があります。429が返ったら止め、アカウントの制限・クレジット・再試行間隔を確認します。待つことで短い制限期間がリセットされる場合はありますが、クレジットは増えず、成功も保証されません。

    4. 結果を記録するメモを作る¶

    同じフォルダーにevidence.mdを作り、下の見出しを貼って保存します。各レッスンの後に短い出力と自分の説明を追記します。Pythonプログラムではありません。見出しは英語のまま使い、説明は日本語で構いません。

    evidence.md
    # Week 5 evidence
## 18 — Components, tools, agents, workflows
## 19 — Integration and model connection
## 20 — Ingestion, retrieval, answer, sources, evaluation
## 21 — Function tool, query tool, ToolSpec and utility tools
## Quiz 1
## 22 — Tool calls, Bob memory, RAG and handoff
## 23 — Events, loop, flow diagram and shared counter
## Quiz 2
## Completion — complete/incomplete and limitations

    以後のファイルは、ファイル → 新しいテキストファイル → 名前を付けて保存で、指定どおりの.py名をヘルパーの隣に付けます。ブロックを順に貼り、Ctrl + S／Command + Sで保存します。.venvやlessons内には入れません。

    1つずつ作って実行します。先に全部作る必要はありません。各ページ末尾の一覧でファイルと結果を確認し、後からimportする以前のファイルも残します。全体では必須の小さなプログラム17個と、任意の評価用1個があります。準備の段階で全部を理解・作成する必要はありません。

    準備の確認：配布ヘルパー、.venv、.env、evidence.md、dataset-source.json、data/persona_0.txt〜data/persona_9.txtがそろっていますか？まだmy_*.pyは不要です。最初の1つはLlamaHubのレッスンで作ります。

    必要なときのヘルプ¶

    コマンドが止まった場合は、該当する説明を開いてから先へ進みます。

    初回のメッセージを読む¶

    インストールとモデル読み込みのメッセージ
    表示・段階 行うこと
    Collecting、Downloading、Installingが続く インストール中です。入力待ちに戻るまで次の行を実行せず待ちます。
    No broken requirements found. 依存関係の確認に通りました。データ取得へ進みます。
    Downloading ten public persona records... 10件の取得中です。Saved 10 persona files...まで待ちます。代替元の表示だけでは保存完了ではありません。
    No complete model cache...、Loading weights 最初の完全なモデル取得には通信が必要です。以後のLoaded the cached CPU embedding model locallyはHFへ接続せず読めた意味です。各演習の完了出力を待ちます。
    モデル取得時にHF_TOKENを勧める警告 この公開モデルにトークンは不要です。完全なキャッシュがあれば次からローカルで読みます。
    pipのhuggingface-hub ... does not provide the extra 'inference' 埋め込み用の接続パッケージが、現在のHubにはない古い任意機能名を要求しています。この警告だけでは検証時のローカル埋め込みは失敗しませんでした。終了後にNo broken requirements found.と演習の結果を確認し、指定バージョンを維持します。
    PyTorchのmacOSではredirects非対応という表示 検証時は、この表示があっても完了しました。続く期待結果で判断します。
    Run incomplete、エラーの詳細、0以外の終了値 未完了です。下の対処表を使い、完了とは記録しません。

    途中で止まった場合¶

    エラーに合う次の操作を探す
    表示・状態 次の操作
    python: can't open file ターミナルの場所、ヘルパーの隣に保存したファイル名、.py.txtになっていないかを確認します。
    版が違う・表示されない 現在の第5週ZIPからweek05_common.pyだけを入れ直し、python week05_common.pyを実行します。.env、データ、自作プログラムは残します。
    ModuleNotFoundError 上の手順で今週の.venvを有効にし、python -m pip install -r requirements.txtを再実行します。第4週へは入れません。
    データ取得が止まる HTTP 503はサーバー側の失敗なので後で試します。通信のタイムアウトなら接続を確認します。チェックサムの不一致は、元のファイルが不完全か変化した意味です。これらの失敗時は人物像を保存しません。表示を教員へ伝えます。
    persona_*.txtが不足 python prepare_personas.pyを実行します。不完全なdataを上書きできない場合はdata-backupへ名前を変えて残し、再取得します。
    埋め込みモデルを読み終えない 通信と空き容量を確認して同じプログラムを再実行します。繰り返し失敗する場合はプログラムを閉じ、.cache/huggingfaceを.cache/huggingface-backupへ変え、安定した接続で再取得します。データとコードは残します。取得にGroqのトークンは使いません。
    索引がない・不完全 10件の取得後にpython my_ingest.pyを実行します。途中のDBがある場合は利用中のプログラムを閉じ、alfred_chroma_dbをバックアップ名へ変えてから作り直します。
    NameError、TypeError、ValueError 表示されたファイル名と行番号で、名前、引用符、字下げを教材の該当箇所と比べます。
    Groq 401 ローカルの.envのキーを確認します。表示や提出はしません。
    Groq 403／404 今週のモデルIDと利用権限を確認します。第4週の設定をコピーした場合は手順3でモデル行を置き換えます。
    Groq 413 小さいデータと短い依頼を使います。待っても大きな入力は小さくなりません。
    Groq 429 停止して手順3の制限についての説明を確認します。
    flow.htmlが真っ白 レッスン23の作図の確認へ進みます。現在のヘルパーは図のライブラリをHTMLに含めるため、閲覧に通信は不要です。

    今の確認項目を直してから、それに依存するプログラムへ進みます。相談時はファイル名、コマンド、エラーの種類を記録し、.envやキーは含めないでください。
